# Verdict AI — Design Prompt (Claude Design)

Спроектируй веб-приложение "Verdict AI" — платформа для анализа результатов A/B-тестов с AI-агентом. Стиль: чистый, минималистичный, как Claude.ai / ChatGPT (светлая + тёмная тема, спокойная типографика, много воздуха, акцентный цвет один).

## Стек и инструменты реализации
- **Backend**: FastAPI (Python) — REST/WebSocket API для чата с агентом, онбординга, загрузки md/csv/parquet, тестов, настроек
- **Frontend**: React (TypeScript), Streamlit отклонён из-за ограниченных возможностей кастомизации UI. Компонентный UI-кит — shadcn/ui + Tailwind CSS, чтобы держать вид максимально близким к макету и Claude.ai/ChatGPT-стилю
- **Render (дизайн/прототип экранов)**: Claude (Claude Design / Claude Code) — прототип экранов делать с учётом стека (React-компонентная разбивка, а не монолитный HTML): чёткое разделение на переиспользуемые компоненты (сайдбар, чат, карточка теста, таблица тестов, модалки), состояния загрузки/ошибок должны соответствовать тому, как их отдаёт FastAPI-бэкенд (async-статусы: "агент анализирует данные" — long-running задача с поллингом или SSE/WebSocket, а не мгновенный ответ)

## Экран 1 — Регистрация / Вход
- Форма: email, пароль, (опционально OAuth Google) должен быть рабочий e-mail
- Переключение Регистрация ↔ Вход
- Минимализм, по центру экрана, без сайдбара

## Экран 2 — Онбординг
Двухчастный флоу:

**2a. Форма** (короткая):
- имя
- роль (admin/analyst/product/marketer/other). Роль первого зарегистрированного пользователя компании — всегда admin
- название компании/проекта
- основная цель использования (чекбоксы: анализ A/B тестов, поиск инсайтов, отчёты для команды)
- загрузка md-файла с описанием компании и продукта (drag&drop зона, формат: .md, обязательное поле). Рядом — ссылка/кнопка "Скачать шаблон .md", шаблон содержит секции: индустрия/ниша, размер компании, тип продукта (B2B/B2C/marketplace/other), сайт (опционально); описание продукта (что за продукт, функция, как работает, этапы использования); типы тестов (по пользователям, switchback, кластерные, ценообразование и др.); метрики (главные, второстепенные, guardrails). Показать имя файла + размер после загрузки, состояние ошибки загрузки — отдельно.

**2b. Чат-интервью**: после формы — экран чата. Агент сначала анализирует содержимое загруженного md, затем задаёт вопросы двух типов:
- уточняющие по фактам из файла (например "правильно понял, что тесты у вас в основном по конверсии?")
- методологические — про ограничения эксперимента (SUTVA violations, network effects, spillover, кластеризация, сезонность и т.п.), но не по фиксированному чек-листу, а адаптивно: только когда из md видно, что риск релевантен (например marketplace/social-продукт → вопрос про spillover между пользователями, geo-тесты → вопрос про spillover между регионами)

Формат — короткое интервью с ветвлением: 3-4 базовых вопроса, дальше агент углубляется доп. вопросами только если ответ пользователя указывает на риск. Пользователь поправляет через диалог. Внизу кнопка "Всё верно, начать работу"

## Экран 3 — Основной интерфейс (после онбординга)
Layout как в Claude/ChatGPT:
- Левый сайдбар (сворачиваемый): кнопка "Новый тест" сверху, ниже список созданных тестов (история, как список чатов), внизу — пункт "Все тесты" и блок с именем пользователя. Клик по имени пользователя открывает всплывающее меню (как в Claude.ai): настройки, тема (светлая/тёмная), помощь/документация, выход
- Центральная область — чат с агентом (дефолтный вид: пустой стейт с приветствием + кнопка "Создать новый тест")
- Верхняя панель: название текущего теста/чата, статус (в работе/готово)
- Раздел "Все тесты" (по клику из сайдбара) — отдельная страница со всеми проведёнными тестами в табличной форме. Колонки таблицы: название теста, гипотеза, статус (в работе/готово), краткие результаты, решение (принято/отклонено/на паузе и т.п.), дата. Клик по строке — переход в чат этого теста.

## Экран 4 — Создание нового теста (карточка)
Модальное окно или отдельный шаг перед стартом чата с полями:
- Название теста (текст)
- Гипотеза / что тестируем (текстовое поле)
- Тип теста: (select: по пользователям, switchback, cluster etc)
- Количество групп (select: A/B, A/B/n, multivariate)
- Номер задачи в tasktracker (Jira, Kanban etc)
- Сегмент/аудитория (текст, опционально)
- Период теста (date range picker, опционально)
- Прикрепление файла с данными (drag&drop зона, форматы: csv, parquet, xlsx; показывать имя файла + размер после загрузки)
- Кнопка "Запустить анализ"

## Экран 5 — Обработка / результат
- После сабмита карточки — переход в чат этого теста
- Статус "Агент анализирует данные..." (loader/progress)
- Результат приходит как обычное сообщение агента в чате: текст выводов + возможность прикреплённых графиков/таблиц
- Пользователь может продолжать диалог с агентом по этому тесту (уточняющие вопросы, углубление в конкретный срез)

## Экран 6 — Настройки
Отдельная страница (открывается из меню профиля), с разделами (табы или боковой саб-нав):
- **Профиль**: имя, email, пароль (смена), роль (только просмотр для не-admin)
- **Компания**: название, md-файл описания компании/продукта (просмотр текущего, кнопка "Загрузить новый / обновить"), доступно на редактирование только admin
- **Команда**: список пользователей компании с ролями (admin/analyst/product/marketer), у admin — возможность пригласить нового участника (по email) и менять роль/удалять участников; у остальных ролей — просмотр списка без права редактирования
- **Тема**: светлая/тёмная/системная
- **Роли и права**: admin — полный доступ (управление командой, настройками компании, всеми тестами); analyst/product/marketer — создание тестов, просмотр всех тестов компании, работа в чате с агентом, без доступа к разделам "Команда" и "Компания"

## Экран 3/5 — Многопользовательский чат по тесту
Тест принадлежит компании, не одному юзеру — несколько сотрудников одной организации могут одновременно находиться в чате одного теста.
- Сообщения в чате помечены автором (имя/аватар), не только "агент/я"
- Обновления чата в реальном времени для всех участников (WebSocket broadcast по test_id, не поллинг только для себя)
- Индикатор "кто сейчас печатает" / кто онлайн в этом чате (опционально, как presence в Slack/Notion)
- Конфликт одновременных запросов к агенту: если один юзер уже отправил вопрос и агент отвечает (статус "анализирует"), второй юзер видит этот же статус, не может параллельно запустить новый анализ поверх — очередь запросов к агенту per test_id
- История чата — общая на тест, доступна всем участникам компании с правами на тест (см. роли в Экране 6)

## Цветовая гамма
Акцент: Indigo/Violet — модерн, AI-вайб, нейтрален к light/dark.
- Accent: `#6366F1` (indigo-500), hover `#4F46E5`, active `#4338CA`
- Accent-soft (фон бейджей/чипов агента): `#EEF2FF` (light) / `#1E1B4B` (dark, ~20% opacity)
- Light theme: bg `#FFFFFF`, surface (сайдбар/карточки) `#F7F7F8`, border `#E5E5E8`, text-primary `#1A1A1E`, text-secondary `#6B6B76`
- Dark theme: bg `#161618`, surface `#1E1E21`, border `#2E2E33`, text-primary `#EDEDEF`, text-secondary `#9B9BA3`
- Статусы: success `#10B981`, warning `#F59E0B`, error `#EF4444` — единые для обеих тем, только фон-подложка меняется
- AI-визуальные элементы (акцент "интеллекта", не декор ради декора):
  - тонкий gradient indigo→violet (`#6366F1`→`#8B5CF6`) на: аватар агента, loader "анализирует данные", progress-бар long-running задач
  - subtle glow/pulse-анимация вокруг аватара агента во время генерации ответа (как typing indicator, не мигающий спам)
  - иконки-стрелки/sparkle (✦) только у элементов, реально связанных с AI-действием (кнопка "Создать тест" с AI-анализом, статус агента) — не сыпать по всему интерфейсу
  - графики/таблицы результатов — нейтральная палитра (не accent), чтобы accent однозначно читался как "это UI/AI", а не как data-цвет

## Типографика
- UI-шрифт: Inter (или system-ui fallback: -apple-system, Segoe UI) — как в Claude.ai/ChatGPT
- Моноширинный (код, числа в таблицах результатов, id теста): JetBrains Mono / ui-monospace
- Размеры: base 14-15px, заголовки экранов 20-24px, второстепенный текст 12-13px. Line-height свободный (1.5+) для чата, плотнее (1.3) для таблиц

## Ошибки и edge-состояния анализа агента
- Статусы задачи: queued → analyzing → done / failed (не только loading/готово)
- failed показывается как сообщение агента в чате с причиной: битый файл, не распознаны колонки control/variant, таймаут обработки, пустой датасет после фильтрации
- К сообщению об ошибке — кнопка "Повторить анализ" и (если причина в файле) "Загрузить другой файл", не просто текст без действия
- Таймаут long-running задачи — показать промежуточный статус ("это занимает дольше обычного") после N секунд, не просто бесконечный спиннер

## Права на уровне теста
- Тест принадлежит компании целиком, не создателю: любой участник компании с доступом к тестам (analyst/product/marketer/admin) может писать в чат теста и видеть результаты
- Редактирование карточки теста (гипотеза, метаданные) и удаление — только автор теста или admin, остальные — read+chat
- Действие "удалить тест" — подтверждение (модалка), не однокликовое

## Версионирование md-файла компании
- При загрузке нового md-файла компании — старая версия не затирается молча, помечается версией/датой
- Тесты, созданные до обновления, хранят ссылку на версию md-контекста, на которой строился анализ агента (бейдж в карточке теста: "контекст компании v2 от 12.03")
- В настройках → Компания — история версий md со скачиванием предыдущих

## Пустое состояние "Все тесты"
- Если тестов ещё нет: иллюстрация/иконка + текст ("Пока нет ни одного теста") + кнопка "Создать первый тест" — тот же CTA, что в пустом чате

## Уведомления
- Бейдж непрочитанного в сайдбаре у теста, если другой участник компании написал в чат / агент выдал результат, пока юзер не в этом чате
- Общий счётчик непрочитанных на пункте "Все тесты" / иконке профиля (опционально)
- Тост-уведомление при завершении long-running анализа, если юзер ушёл со страницы результата в другой раздел приложения

## Лимиты загрузки файлов
- md (онбординг/компания): максимум 5 МБ
- csv/parquet/xlsx (данные теста): максимум 50 МБ на файл
- При превышении — состояние ошибки в drag&drop зоне с явным текстом лимита, без молчаливого обрезания файла

## Мобильная версия
- Explicit out-of-scope для MVP: показывать read-only баннер "Для полного функционала используйте desktop" при ширине < 768px
- Чат и таблица тестов — минимально доступны для просмотра (read-only), создание теста и настройки — недоступны с мобильного в MVP

## Общие требования
- Responsive, приоритет desktop
- Тёмная и светлая тема
- Состояния: пустой сайдбар (нет тестов), список тестов, активный чат, загрузка файла, ошибка загрузки файла

## Открытый вопрос
Поля карточки теста — стандартный набор для A/B-тестов. Нужно уточнить формат/колонки, которые ожидает агент от CSV/parquet (control/variant группы и т.д.), и отразить это в форме или подсказке рядом с загрузкой файла.
